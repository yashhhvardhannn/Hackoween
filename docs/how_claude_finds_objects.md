# How Claude finds the object from the image

Claude never receives object data. The engine's API returns only the robot's own state (position, heading, holding yes/no, retry count) and action results (moved, collided, pickup success, drop in-zone), and `tools/leak_check.py` blocks every request that would contain an object name, colour, shape, position or count. At each step the agent sends Claude the typed command, the latest 640×480 camera frame (`GET /look`) as an image block, the single-ray depth reading and a one-line text summary of earlier steps. A new frame is taken only after a move or turn. Two thin guide lines are drawn on the frame. They mark the strip of floor the 0.6 m-wide robot will sweep when driving straight, with distance ticks at 0.5–3 m. They come from fixed camera geometry only (height 0.5 m, 10° tilt, 90° field of view), so they add no object information. From the pixels, Claude names the object that matches the command by colour, shape and relative size. For reasoning commands such as "the tallest object", it first scans the room in 90° turns and compares what it saw across views. It then turns by the horizontal pixel offset (about 14° for 80 pixels from the centre column), judges the distance from how low the object's base sits in the frame, and drives with move/turn only. It calls pickup when the base reaches the bottom edge of the frame. To deliver, it finds the flat drop-zone marker the same way. Every tool call carries Claude's own `observation` (what it sees) and `reasoning` (why this action), which are written to the JSONL log next to the PNG frame Claude was shown. The logs therefore show the identification coming from the image. When a move reports `collided: true`, Claude backs up, picks a route where the guide strip is clear, and tries again.
